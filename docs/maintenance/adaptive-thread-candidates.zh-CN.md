# 自适应帖子投递候选

已加载且明确未归档的论坛帖 MESSAGE_CREATE 会比较现有准确 ETS 关注计数与该社区在线索引的唯一用户数，人数相等时走关注方向。关注方向保留 member_ids → for_users；在线方向对每位唯一在线用户即时探测一次 ETS 成员关系，命中后展开所有设备。候选 map 以 SID 去重，再合并直接提及与浏览会话。

读取关注计数为 O(1)，不会为选择方向构造关注列表。现有加入与退出幂等维护计数，handoff 导入从关系重建计数。在线索引继续按会话 map 引用变化失效，不跨消息缓存成员关系或权限。

计数未知、归档或缺帖、元数据缺失、其他事件与非论坛父频道沿用原路径。缺失存储保留原错误或快照行为。最终兴趣、viewer、pending、权限、passive 与浏览租约检查不变。数量比较只是首版启发式，ETS 探测和 map 查找成本不同，不能据此承诺 CPU 提速。

交接包提供的 `guild_adaptive_candidates_tests.erl` 在隔离验证目录运行，不新增到产品测试目录。它覆盖两方向、十万关注、四千在线、小帖、相等、空集、全离线、多设备、关系变化与导入。使用 `ADAPTIVE_ORACLE` 和仅验证时的 `export_all`，还会与整合前 dev 的 gate 精确比较候选 map 与最终 SID/session 集合，包含十万关注、四千在线、两千浏览 fixture；小 fixture 验证权限撤销、直接提及、浏览过期、pending/viewer/passive、归档恢复、未知计数与缺表行为。本次仅把隔离 oracle harness 的超时从30秒改为180秒，不延长产品RPC预算，也不运行容量压测。具体命令和结果见交付包验证说明。
