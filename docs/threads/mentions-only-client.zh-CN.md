# 帖子通知客户端维护说明

帖子的成员通知 UI 仅提供“仅提及”和“关闭”。桌面顶栏、帖子上下文菜单、侧栏移动菜单和移动端频道详情通知弹层共用同一个帖子菜单构造器。移动弹层必须写入帖子成员 flags，不能再写普通频道通知覆盖值。

旧 `ALL_MESSAGES` 按 `ONLY_MENTIONS` 读写。没有显式选择的成员，仅继承父级“关闭”；父级其余通知级别均解析为仅提及。显式成员选择仍覆盖继承值。静音独立处理。普通频道和 DM 设置、未读徽标、论坛新帖设置保留原有选项。

`Message.threadMentionWarnings` 承载可选公开字段 `thread_mention_warnings`。旧响应缺字段时得到空数组。局部更新没有该字段时保留原值，显式空数组或 undefined 则清空。消息相等性判断和 JSON 序列化都包含原因，确保仅补充 warning 的网关更新能刷新消息界面。转发消息快照不继承这些投递决策。

紧凑和普通消息布局均在消息旁显示非阻塞说明，支持 `role_group_too_large`、`role_union_too_large`、`role_index_unavailable`。未来未知原因与历史失败 flags 不生成新提示。说明不含人数或身份，并从复制消息文本中排除。原始 mention payload 和 WS 提及显示保持不变。

三个提示已提供英文与简体中文目录条目，其余语言显式使用英文回退，等待正式本地化。候选历史记录称 34 个语言目录通过严格编译，不代表本次整合已复测；后续提取和翻译时须保留这些回退条目。

前端可独立升级以接受可选字段，但服务端规则须等 API、worker 和 Gateway 的决策能力全部就绪才启用。部署前端不能替代服务端资格检查。回退旧前端后可能再次出现“全部”选项，服务端仍须自行强制帖子规则。通知规则与十万成员上限分开回退，不能截断现有成员关系。

本地桌面/浏览器通知仍使用既有通用提及匹配，`@everyone`/`@here` 在该独立路径中仍可能被视为提及。本改动不宣称关闭该路径；Gateway 设备 Push 的抑制由服务端实现。论坛新帖创建的通知级别解析保持原样。

本次整合的实际验证命令与结果随交付包单独列出。历史候选测试和构建不等于当前源码的验证；全 app 类型检查、实际浏览器视觉验收以及真实混合版本部署必须独立报告。

帖子 MESSAGE_CREATE 走版本化专用网关 RPC。旧网关不认识该入口时明确失败，不退回可能泄露私有决策或恢复全帖广播的旧入口。已升级网关在角色能力尚未就绪时只保留直接提及；先升级所有 Gateway，再部署 API/worker 并等待租约齐全，最后启用角色通知及客户端提示。失败调用可能发生在消息已持久化之后，运维应依据日志和消息 ID 排查，不能把这一点当作已具备消息 outbox 恢复。
