# Cassandra 本地元数据缓存与尽力通知

缓存数据只在 API／worker 进程内保存，Valkey 仅广播失效，不保存缓存值，不参与数据库提交。

## 读取与过期

频道元数据只含 ID、社区 ID、类型，最多五万条 LRU，固定五分钟；社区快照最多一万条，固定一秒。有效期从回源开始计算，访问不续期，过期查询不回填。保留每批一百 ID、最多 1024 不同键填充和同键查询合并。不存在或错误不缓存。

缓存不替代权限、可见性或完整实体读取。关闭 Cassandra 新缓存时仍沿用原路径。开关默认均关闭；PostgreSQL 的数据库通知路径不变。

## 写入与广播

写入前后清理本进程对应 ID 和在途填充，数据库操作结束后仅向有界后台队列投递失效事件。数据库成功不会因为通知失败而失败；数据库错误或未知结果按原语义返回，同时尽力失效，不自动重试数据库写入。条件写明确未应用时不广播。

修改一个帖子不会清空其他帖子或社区缓存。批次去重，未知 ID 回退为对应类别清空，完全无法识别才清空两类。无关字段与普通非元数据写入不广播。清表按类别清空。

通知包含格式版本、随机事件 ID、来源进程、类别和标识列表或类别清空标记，不包含业务内容或凭据。命名空间由配置的 instance.baseDomain 与 keyspace 共同派生。同一部署各进程必须一致；不同部署共用 Valkey 时必须使用不同命名空间。

每个启用缓存的进程使用两条专用连接：发布命令超时 250ms 且禁止离线命令积压，订阅初始失败后台以 500ms 至 5s 退避重试。每批至多一百 ID，待处理至多 1024 个不同实体键，超量合并为类别清空；同时只发布一批，失败丢弃该批，不无限重试。停机最多等待一个发布超时后关闭专用连接。

断线、订阅错误、启动或重新订阅成功都会清空旧本地状态，随后仍允许固定 TTL 缓存。Pub/Sub 不持久，遗漏、进程崩溃及直接 CQL 维护写入由过期兜底。原生数据库 TTL 到期没有通知。此机制不承诺瞬时一致，也不改变 Cassandra 副本一致性。

## 升级与观测

原 JetStream 持久意图日志停止使用，不自动删除已有流或历史。统一更新所有 API／worker，避免旧写入屏障和新协议混跑。禁用缓存可回退，但不是生产数据库迁移。

指标包括命中、回源、精确失效、类别清空、目标识别回退、通知成功与失败、合并与溢出、队列水位、订阅状态，不含实体标识。持续通知失败增加数据库回源压力，但不永久停用缓存或阻止相关元数据写入。

真实集成测试只在明确授权的独立 Cassandra keyspace 和独立 Valkey 进程上运行；普通回归不得连接开发或生产数据库。压测另行安排，集成正确性不代表容量结果。

## 已读优化的独立开关

`FLUXER_READ_STATE_COMBINED_GATEWAY_RPC_ENABLED` 控制将清通知与 MESSAGE_ACK 派发合为一次网关 RPC；先部署支持该方法的网关，再启用 API 开关。数据库已读落库与两个副作用的先后顺序不变，清通知失败仍尝试派发，不把不同用户的已读合并。已有传输层重试语义不因此变成严格一次执行。
