# 帖子浏览订阅

浏览订阅只为正在打开的论坛或媒体帖子增加当前 Gateway 会话的实时投递资格。它不写入正式成员关系，不扩大目录、搜索、关注列表未读或普通通知范围。直接用户提及保留现有通知规则。

## 协议

扩展现有 `LAZY_REQUEST`，浏览请求携带顶层 `thread_watch_nonce`，各服务器的 `thread_watches` 为该服务器的完整目标集合。缺省表示不修改，空数组取消。

```json
{
  "thread_watch_nonce": "connection-epoch:request-number",
  "subscriptions": {
    "guild-id": {"thread_watches": ["thread-id"]}
  }
}
```

会话进程串行校验跨服务器去重后的最终集合，最多 10 个帖子。切换时可在同一请求清空旧服务器并设置新服务器，按最终集合计数。超限拒绝整个浏览更新、保留原租约及到期时间；同包其他普通订阅不受影响。

超限后，前端立即用独立请求续期服务端已接受且仍在显示的帖子，后续按常规周期续期该集合；未接纳的帖子保留超限提示，不自动替换旧帖子。显示集合变化时重新提交完整目标集合，关闭旧帖子腾出额度后即可接纳新帖子。

全局额度错误通过 `THREAD_WATCH_ACK` 返回：

```json
{"nonce":"request-number","ok":false,"code":"THREAD_WATCH_LIMIT_EXCEEDED","limit":10,"requested_count":11}
```

成功请求按服务器确认，确认发生在租约安装之后。`thread_ids` 是实际接受的集合；无权访问、不存在或非论坛帖子的标识不会被接受。`resync_thread_ids` 标识首次建立或已过期的关系。`expires_at` 为服务端 Unix 毫秒时间。

```json
{"nonce":"request-number","ok":true,"guild_id":"guild-id","thread_ids":["thread-id"],"resync_thread_ids":["thread-id"],"expires_at":1792100000000}
```

元数据暂时不可用时返回 `ok:false` 和 `THREAD_WATCH_UNAVAILABLE`，不把查询故障解释成帖子删除。没有确认不能视为订阅成功。

## 生命周期与数据路径

- 实际消息页面持有浏览引用，最后一个引用释放时立即退订；后台页面继续保持引用。
- 前端每 4 分钟续期，抖动 ±15 秒；租约在服务端最后一次有效请求后 10 分钟到期。确认超时重试；休眠或连接恢复后立即重申集合。
- 前端单独跟踪成功确认的 `expires_at`，重试和失败回包不延长期限；到期撤销确认并明确提示实时更新已过期。只有新的有效租约确认才能恢复可用状态，并重新刷新消息窗口。
- 前端在确认后刷新当前消息窗口，常规续期不拉历史。恢复保留阅读范围、合并并发新增/编辑/删除/反应事件；没有完整事件日志或逐事件重放保证。
- 历史窗口补拉期间，边界外新增消息保留后续分页标记，避免已收到的新消息消失后无法补拉。普通加载、翻页或缓存跳转接管窗口时，旧浏览补拉立即失效，不能覆盖新窗口或清除其加载状态；待普通请求完成后按新的阅读窗口重新补拉，关闭帖子或连接代次变化后停止重试。
- 浏览租约使用独立 ETS 正反索引和到期索引，不改写 guild 的在线 `sessions` 映射。续期不查询数据库、不触发目录或成员列表同步。
- 缺失帖子元数据通过内部 `thread_watch_contexts` RPC 批量读取，单个 guild 同时最多一个 100 帖子批次；同帖等待请求合并。支持归档帖子和活动缓存淘汰的帖子。
- 元数据回包每次最多唤醒 256 个等待会话，通过后续消息继续处理；退订直接删除待查询索引，快速切换不积累历史队列节点。
- 内容及帖子元数据事件合并正式成员和浏览会话候选并按会话去重，再执行权限检查；浏览不会自动订阅成员名单、在线状态或输入状态。
- 到期清理每批最多 1000 个关系；投递直接判断期限，不依赖清理进度。迁移保留原到期时间，先恢复仍有效且会话存在的租约，再仅恢复这些租约引用的上下文，避免到期或未恢复会话留下孤立缓存。会话结束、帖子删除及功能关闭清理关系。

## 检查与观测

功能测试位于 `test/*thread_watch*tests.erl`、前端 `ThreadWatches.test.ts` / `ThreadWatchWindowRefresh.test.ts`，API 的 `ThreadWatchContexts.test.ts` 和 RPC 线程测试覆盖批量读取及协议。

指标包括 `fluxer_gateway_thread_watch_leases` 和固定 `operation` 标签的 `fluxer_gateway_thread_watch_operations_total`，记录更新、额度拒绝、缓存命中/未命中、批量读取、读取失败、到期清理及累计处理微秒。租约指标读取每个存储的计数行，不遍历租约。

本次实现不执行大规模压测。单服务器 10 万/20 万会话、热点帖子数千浏览者、重连峰值以及实际容量和延迟，由独立压测会话验证；不能将单元测试结果作为容量结论。
